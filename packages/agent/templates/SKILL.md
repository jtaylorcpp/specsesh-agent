# specsesh

specsesh drafts OpenSpec changes, builds them task by task with agent loops, and keeps the user, the principal, in charge of every decision. This skill was generated by specsesh {{version}}.

## Before the first command

Run `npx specsesh llm` (or `specsesh llm` when it is installed) and read the output. It is the guide to the workflow, the rules and every command, and it matches the installed version. Read it again if the CLI says something it doesn't explain.

## How to work

1. **Map the request to the workflow.** Spec something new with `specsesh change draft <change> --intent "<the user's words>"`. Implement a drafted change with `specsesh change build <change>`. Finish it with `specsesh change close <change>`. One task: `specsesh task <change> <task-id>`.
2. **Say what you'll run before running it.** Runs make model calls and can take minutes. Commit or stash first: a dirty tree is refused.
3. **Follow the output.** Every blocked or finished run ends with the exact command to run next. Use it; don't guess loop ids.
4. **Never approve or answer as the principal on your own.** Show the user the review or the question, and run `change approve`, `change build <change> "<answer>"` or `task answer --by principal` only with their decision.
5. **Show the diff and stop.** specsesh never commits. Show `git status` and `git diff`, and commit only if the user asks.

## Exit codes

`0` is done. `1` is blocked, exhausted or failed: the output says which and what to run next. `2` is refused before anything ran: fix the cause, since nothing changed.
