# specsesh

specsesh drafts OpenSpec changes, builds them task by task with agent loops, and keeps the user, the principal, in charge of every decision. This skill was generated by specsesh {{version}}.

## Load context as you need it

1. **The map.** Run `npx specsesh llm` (or `specsesh llm` when it is installed) once per session. It's short: which command fits the job, and the rules that always apply.
2. **The command.** Before you first use a command, run `specsesh <command> help`: `change`, `task`, `agent` or `durable`. It prints that command's usage and how it behaves: flags, outputs, refusals and exit codes.

Don't read the help for commands the task doesn't need.

## How to work

- **Say what you'll run before running it.** Runs make model calls and can take minutes. Commit or stash first: a dirty tree is refused.
- **Follow the output.** Every blocked or finished run ends with the exact command to run next. Use it; don't guess loop ids.
- **Never approve or answer as the principal on your own.** Show the user the review or the question, and run `change approve`, `change build <change> "<answer>"` or `task answer --by principal` only with their decision.
- **Show the diff and stop.** specsesh never commits. Show `git status` and `git diff`, and commit only if the user asks.
