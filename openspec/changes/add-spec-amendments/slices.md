1. `add-spec-amendments`: An `amend-spec` escalation from the task loop carries the proposed amendment: the target spec delta under `openspec/changes/<change>/specs/` and the full replacement text of that file, which the task agent now puts in its `amend-spec` reply. A new loop decision records that an amendment was applied.
2. `add-spec-amendments-judge`: The group judge's `amend-spec` finding carries the target spec delta path and the full replacement text, and the group loop's escalation passes them through. Follows add-spec-amendments.
3. `add-spec-amendments-cli`: `pnpm change build <change>` shows a proposed amendment as a diff against the file on disk, along with the question. `pnpm change build <change> --amend` writes the amended delta and runs `openspec validate <change> --strict`. If validation passes, the blocked loop resumes with the decision recorded as "amendment applied". If it fails, the file is restored, nothing resumes and the errors are printed. A text answer works as it does today. Follows add-spec-amendments-judge.
