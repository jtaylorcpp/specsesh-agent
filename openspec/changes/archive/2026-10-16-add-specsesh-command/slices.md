1. `add-specsesh-command`: `@specsesh/agent/cli` exports `main(argv, deps)`, the `specsesh` command: `agent`, `durable`, `task` and `change` route in-process to the four existing CLIs, `task <change> <id>` implies `run` as `pnpm task` does, and `--help` and `--version` print the usage and the package version.
2. `add-specsesh-package`: A second publishable workspace package, unscoped `specsesh` (`packages/specsesh`), whose only bin `specsesh` runs `@specsesh/agent/cli` and whose dependencies are `@specsesh/agent` at the same version plus the three Node peers, so `npx specsesh …` works with nothing else installed; a README for npm, and pack:check installs and runs it. Follows add-specsesh-command.
3. `add-npm-release-workflow`: A GitHub Actions workflow that, on a `v<version>` tag, checks, packs and publishes `@specsesh/agent` then `specsesh` to public npm through trusted publishing (OIDC) with provenance, after a release check holds the tag, both manifest versions and the packed dependency to one version. Follows add-specsesh-package.
4. `name-specsesh-in-change-output`: The change CLI's usage, refusals and next-command lines name `specsesh change …` instead of `agentscript-change …` and `pnpm change …`, and this repository's `pnpm change` runs `specsesh change`. Follows add-specsesh-command.
5. `name-specsesh-in-task-output`: The task CLI's usage, resume hints and next-step lines name `specsesh task …` instead of `agentscript-task …` and `pnpm task …`, and this repository's `pnpm task` runs `specsesh task`. Follows name-specsesh-in-change-output.
6. `use-published-ontology`: Replace `packages/agent/src/openspec` and the OpenSpec Markdown readers with a dependency on the public `@specsesh/ontology`, keeping `@specsesh/agent/openspec` as a re-export. Follows add-npm-release-workflow, and the first public publish of `@specsesh/ontology` from its own repository.
